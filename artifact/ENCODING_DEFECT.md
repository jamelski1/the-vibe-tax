# The CP437 encoding defect (disclosed in the paper)

At prompt-generation time, non-ASCII characters were corrupted by a UTF-8 → CP437 mishandling:
the UTF-8 bytes of a character were written/read through the wrong code page. For example the arrow
`→` (U+2192, bytes `E2 86 92`) became the mojibake `ΓåÆ`, and the Chinese multilingual framing
`帮我…` became `σ╕«µêæ…`. It is **losslessly recoverable**: `s.encode("cp437").decode("utf-8")`
restores the original text, confirming the defect changed the *encoding*, not the content.

Audit + robustness script: **`encoding_robustness.py`** (run it to regenerate everything below).

## Extent

| where | extent |
|---|---|
| multilingual framing (Chinese is all non-ASCII) | 372 / 501 prompts mojibake; only 129 clean |
| English-condition **problem statements** containing a non-ASCII symbol | **9 of 167 problems**, corrupted in *every* condition (the statement is shared) |

So it is a **dataset-wide** defect, not multilingual-only.

## The 9 corrupted-statement problems (affect all four conditions)

| problem | difficulty | mangled → recovered |
|---|---|---|
| lcb/3540 | medium | `ΓåÆ` → `→` |
| lcb/3659 | medium | `ΓåÆ` → `→` |
| lcb/3733 | hard | `ΓåÆ` → `→` |
| lcb/3805 | medium | `ΓåÆ` → `→` |
| lcb/3783 | hard | `ΓåÉ` → `←` |
| lcb/3739 | hard | `├ù` → `×` |
| lcb/3588 | hard | `ΓÇÖ` → `’` (curly apostrophe, cosmetic) |
| lcb/3674 | hard | `ΓÇï` → U+200B zero-width space (invisible) |
| lcb/3794 | medium | `ΓÇï` → U+200B zero-width space (invisible) |

Six have math-symbol corruption (→, ←, ×); three are cosmetic.

## It does NOT change the study's headline

The terse-vs-detailed result is unchanged when the 9 corrupted-statement problems are excluded
(all compile-rate, needs no tests; regenerated by `encoding_robustness.py`):

| problem set | NAIVE compile-tax (terse−det) | ROBUST (ours) pass (terse−det) |
|---|---|---|
| all 167 | b=73, c=24, p = 6.4×10⁻⁷ | b=14, c=12, p = 0.85 (null) |
| clean 158 (excl. 9) | b=73, c=21, p = 6.7×10⁻⁸ | b=12, c=11, p = 1.00 (null) |

The naive artifact is unchanged (slightly stronger) and the robust null stays null.

## It did not trigger refusals or safety behavior

Across all 372 mojibake multilingual prompts: 100% produced code, 0 refusals/safety responses. The
models treated the garbled framing as ignorable noise and solved from the intact English problem
body; within-problem, multilingual pass ≈ the same problem's English-register mean (≈ neutral).

## For reproduction

To eliminate the defect entirely you would regenerate the prompts with `encoding="utf-8"` forced
end-to-end in `generate_lcb_prompts.py` and **re-query the models** (the corruption is in the
*prompt the model received*, so re-scoring the stored replies cannot undo it). Re-querying needs
model API access (see README "What is NOT included"). The study does not re-query; it discloses the
defect and shows (above) that it does not affect the finding.
